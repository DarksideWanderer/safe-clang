# 安全模型与实现约束

safe-clang 在受支持的 C++20 子集中检查初始化、拥有权、借用、函数效果和运行时
边界。安全结论依赖 unsafe 实现满足契约，以及编译链、标准库、ABI 和平台正确。
safe 标记本身不能修复不满足契约的底层代码；局部证明和测试也不是端到端可靠性证明。

## 实现分层

| 层 | 入口 | 责任 |
| --- | --- | --- |
| 类型表示 | 原生补丁内的 AST 类型和 ASTContext | 保存规范区域、绑定、投影、函数效果和类型身份 |
| 关系查询 | CircleClassLifetime／CircleFunctionRelation 等共享层 | 分别处理精确身份和方向性替换；保持独立绑定作用域 |
| 声明与调用 | Sema 与 `src/ModuleSafety.cpp` | 重声明、覆盖、impl、转换、模板和调用的契约校验 |
| 数据流 | `src/FlowAnalysis.cpp`、SafetyContracts、SafetyTraversal | 存储／数据来源、权限、初始化、移动、清理和异常路径 |
| 持久化及执行 | serialization、CodeGen | PCM、名称修饰、清理责任和运行行为一致 |

Clang 内部文件包含在 `frontend/clang-22.1.2.patch`；对应结果摘要在
`frontend/source-hashes.json`。原生修改必须更新两者并验证无 fuzz 重放。
共享检查器由构建脚本同步进原生前端，不能在某个 visitor 内另建一套关系求解器。

## 不变量

- 区域身份由所属绑定作用域及参数身份决定，不能凭拼写相同判断；未知不等于
  任意区域或永久区域。没有显式量化也不等于没有返回／静态契约。
- 精确契约身份与可替换性分别检查；共享协变、函数参数逆变和可变位置不变性
  必须按嵌套结构组合，不能用简单擦除绑定或区域替换放宽关系。
- 存储来源与值携带的数据来源分别保存。数据为 static 不授权返回局部句柄地址；
  按值参数的存储、字段存储和所携带外部数据不能混为一谈。
- 来源／可能 moved 状态在分支合并中取保守并集，父借用访问豁免只保留共同事实。
  根来源相同不代表已授权再借用；聚合的每个重叠组成值都须提供证明。
- 共享借用允许复制，可变位置保持写入所需的保存区域。可变视图句柄不授权修改
  只读目标；独占字段不能替共享字段授予别名许可。
- 普通 C++ 移动仍有源析构义务；原生重定位结束对应源生命周期并更新清理标志。
  字段赋值不恢复整个 moved 对象，普通赋值也不恢复已退休的原生存储。
- unsafe 可允许底层操作，不能伪造编译器元数据或跳过受检查函数的生命周期契约。
  noexcept 只描述异常行为，不能授予 safe 调用权限。

## 调用、初始化与异常

每个具体模板实例化及导入 PCM 的模板体接受检查，调用方按函数类型中的来源和
效果检查实参。默认参数、默认成员、基类／成员初始化和数组隐式填充均参与检查。
sizeof、decltype、noexcept 和 requires 等未求值语境不能误当作实际执行。

CFG 覆盖分支、循环、作用域销毁及隐式析构，并补充可能抛出操作到最近词法处理器
的保守状态。构造失败不能视为初始化成功；处理器入口退休 try 内的局部存储。
构造／析构 function-try-block 禁止访问已销毁成员。
全局／TLS 的可达读写、未知调用、临时实参及正常／异常析构都要与活跃借用相容。

字段路径包含完整前缀，退休节点失效所有后代；清理按真实存活叶子执行。
`:=` 的构造失败保留旧值，旧析构抛出则退休目标并清理新临时值；清理前先关闭
对应 live 标志，防止展开时重复析构。按值参数的清理责任跨 PCM 和 ABI 保留。

## unsafe 运行库审计义务

| 范围 | 实现必须保持的条件 | 主要验证入口 |
| --- | --- | --- |
| 算术、边界与转换 | 检查先于危险操作；失败不执行越界转换；结果初始化 | runtime、conversions、bitints、prove_conversions |
| 拥有与借用容器 | 正确对齐、唯一拥有、元素来源有效；部分构造及复制失败回滚；析构安全效果独立验证 | borrowed_containers、mutable_borrows、lifecycle_system |
| 间接／序列存储 | 字段映射与声明的 Owner 区域一致；扩容、替换、析构和返回不丢失来源 | indirect_storage_*、container_factory_regions |
| Pin | 对象存活期间地址稳定、先析构后释放；句柄转移不移址；外部借用保留 Owner | ownership_concurrency、lifecycle_system |
| 线程与锁 | callback 在 safe 中验证；参数／结果活至线程结束；失败路径处理已启动线程；异常解锁 | threads、ownership_concurrency |
| 原子 | 活着的存储、合法内存序、不泄露内部存储引用；不把原子指针等同于目标生命周期证明 | ownership_concurrency |
| 协程 | 支持范围内的帧保存和销毁满足约束；不隐式扩大到借用式任务和任意 awaiter | coroutines |

表中的入口为 `tests/` 内同名 Python 文件或文件组。`unsafe.impl.send/sync`、
`moved.drop`、堆／序列存储、borrow-adoption 和协程标记都是实现义务，不能靠注解
本身获得证明。泛型容器的元素复制、移动、析构及回调仍须独立实例化检查。

## 当前限制

受检查模式限定 C++20／gnu++20；裸指针访问／算术、new/delete、危险转换、内联
汇编、volatile 和未经建模的扩展存储等不能自动获得 safe 权限。
动态有符号算术、除余、移位、下标及转换在适用路径检查；普通 constexpr 调用的
折叠结果不能充当运行时范围证明。safe 编译拒绝破坏检查前提的 fast-math 选项。

union 限于活动成员可追踪的受限存储，generator 限于不保存外部借用的拥有型标量帧。
任意 awaiter、借用异步任务、取消／调度及全部平台 ABI 尚未建立完整支持。
静态初始化、复杂布局和不可证明的来源继续保守拒绝。完整 Circle／Rust 语言范围
及独立 Circle 二进制对照仍未完成，详见 [兼容清单](../compatibility/README.md)。

## 证明边界与完成要求

Z3 转换范围模型有 1,368 个反例查询，要求全部 UNSAT；SAT、unknown、错误或超时
均使检查失败。Lean 验证局部状态、存储退休、分支合并和消耗规则；有限生产状态
空间测试直接检查实际 join／conflict 实现。它们没有机器检查地证明 AST／CFG
提取、整个检查器、异常清理、运行库、LLVM 或平台正确。

N4861 的 UB／库前置条件索引包含 649 个候选段落，保持未证明状态；它不是完整
语义清单，也未穷尽引用的 C／POSIX 规范和所有隐式前置条件。
最终可靠性论证还需要受支持语言的操作语义、实现对语义的精化、每条规则的保持性、
unsafe 库义务证明、PCM／ABI／CodeGen 保持性及实际交付快照的完整验证。

新增关系应先核对固定参考语义，在共享层实现，再加入合法与非法对照用例及所有
相关入口检查，最后运行 [统一验收](VALIDATION.md)。不能用测试数量、拒绝任意
程序或另一个功能的专项通过代替这些义务。
